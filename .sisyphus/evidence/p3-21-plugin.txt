## Design notes
- Uses libloading 0.8 for dynamic library loading
- extern "C" ABI for entry point (stable across Rust compiler versions)
- #[allow(improper_ctypes_definitions)] on PluginCreateFn — trait objects aren't FFI-safe
  per the compiler, but the entry point is only called by Rust code; extern "C" is for
  ABI stability across separately compiled dylibs
- Library handles kept alive in PluginManager to prevent unmapping plugin code
- Plugin discovery: scans directory for .so/.dylib/.dll extensions
- No HashMap used anywhere (BTreeMap not needed either — Vec suffices)
