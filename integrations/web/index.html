An agent-first decompiler.

Unlace is a self-refining decompiler built to be used by agents. It is based on the Ghidra decompiler, written in Rust, and integrates modern features from other open-source decompilers and research. Unlace is an experiment to see how far agents can take self-refining tools.

Source Try it Read blog post
$ unlace decompile ./a.out main
$ unlace decompile ./stripped.bin 0x401040 --addr
$ unlace decompile-all ./a.out --json
$ unlace decompile ./a.out main --option compareform canonical
  • built on Rust · SLEIGH
  • runs in CLI · the browser (wasm) · Ghidra GUI (extension)
  • license Apache‑2.0

        goals
      

      
This project optimizes for three specific goals.


      
    
        
  1. 
          
    01
    
          
    Autonomous Refinement
    
          
    
            LLM agents should drive the majority or all of code writing in Unlace, supported
            by a dataset which directs the models towards quality metrics.
            As such, code is optimized to be used, read, and modified by agents, as well
            as debugged in the context of big dataset competitions like DecBench.
          
    
        
    2. 
        
  2. 
          
    02
    
          
    LLM-Facing
    
          
    
            LLMs are likely to become the main consumers of decompiled code in the future.
            As such, Unlace optimizes to be read by LLMs.
            That means GUI development is largely untouched and UX is on the lower side
            of priorities for this project.
            This also means decompilation text quality and speed are our top priority.
          
    
        
    3. 
        
  3. 
          
    03
    
          
    Tunable
    
          
    
            Based on recent research in decompilation, not all decompiler features are always good.
            Some are useful in only specific contexts.
            As such, every feature is developed in this context: is it always good? How can we know? Can it be enabled dynamically and robustly?
