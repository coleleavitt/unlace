# Original unlace: c_printer, second half (origin/master)

Slug `output-cprinter-b`. Scope: `crates/unlace-output/src/c_printer/` on `origin/master`, files 21 to 41 of the sorted list: `postprocess/dead_assign/segments.rs`, `postprocess/dead_assign/trace.rs`, `postprocess/decls/{insert,locals,mod,names,prune,purity}.rs`, `postprocess/{idents,idioms,labels,lvar_names,mod,repair}.rs`, `ternary.rs`, `tests.rs`, and `trace/{gate,mod,names,pipeline,stack}.rs`. The first half (`cpa/`, `mem_objects/`, `member_path.rs`, `mod.rs`, `postprocess/combine/`, the start of `dead_assign/`) is another teammate's.

The original printer is a text-level pipeline: it prints C as a string, then runs line- and identifier-level passes over it (dead-assignment pruning, declaration insertion, Hex-Rays-style renaming, goto and label cleanup). Main prints from a structured tree (`printc.rs`, `ctreeprint.rs`), so most of these passes have no counterpart because the problem they fix does not arise. The table ranks what is still worth taking.

Main was checked on `origin/main` with `git grep`, because the `unlace-wt-main` checkout is detached at an older commit. Line numbers for master refer to `origin/master`. `notes/archived-master-inventory.md` and `notes/ida-gap/*.md` do not cover these passes, so nothing here repeats them.
