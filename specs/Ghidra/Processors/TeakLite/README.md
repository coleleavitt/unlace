# CEVA-TeakLite

Vendored from aleph-void/TeakLite-SLEIGH (https://github.com/aleph-void/TeakLite-SLEIGH), a fork of SachinVin/TeakLite-SLEIGH (https://github.com/SachinVin/TeakLite-SLEIGH), commit 32d05a51a3e4a3bda7f2a642eafc4a3d7b794fba, MIT License (`LICENSE`, copied from upstream).
`data/languages` hold the upstream SLEIGH, processor and compiler files unchanged; upstream build files, scripts and tests are not vendored.
`teak.ldefs` is upstream's plus the two OakDSP languages.

Languages: `teak:LE:16:default`, `teak:LE:16:modulo`, `oakdsp:LE:16:default`, `oakdsp:LE:16:modulo`.

## OakDSP

CEVA's OakDSP core is the TeakLite predecessor: TeakLite II kept Oak's encodings and added instructions
in Oak's free code space and in operand values Oak reserves (r6/r7 as pointers, 18-bit branch and call
targets, the extra bank-exchange flags, ...). `oakdsp.slaspec`, `oakdsp_tokens.sinc` and
`oakdsp_insts.sinc` are generated by `tools/gen_oakdsp.py` from the teak files and an Oak first-word
map, `tools/oakdsp_oracle.txt` (recorded from IDA 9.5's `oakdsp` module by `tools/oakdsp_probe.py`):
a teak constructor with no Oak-valid word is dropped, a partly valid one is split into copies whose
`ob_N` single-bit constraints cover exactly its Oak words, and `mov Ax, Register` (a0/a1 as the
register-move source, which TeakLite II reassigned to `mma_mov`) is added. Over all 65,536 first words
the result agrees with the map on validity, length and mnemonic except for 510 words the map decodes
only by ignoring reserved bits (aliases of canonical `rep`, `mov ..,icr`, `banke`, `lim`, `swap`,
`min` encodings), which stay undecoded. Registers keep TeakLite II's names (`r7` for Oak's `rb`,
`y0` for `y`, `p0h` for `p`). Regenerate with
`python3 tools/gen_oakdsp.py --unlace <unlace binary> --sleighpath specs`.
