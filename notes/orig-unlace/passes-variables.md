# Original unlace: variable merge, register coalescing, lvar collection and naming

Scope: four passes in `origin/master` `crates/unlace-passes/src/`: `variable_merge.rs`, `register_coalesce.rs`, `lvar_collect.rs` and `var_naming.rs`. Each technique is compared with main, where variables are formed by a port of Ghidra's `merge.cc` (`crates/unlace-middle/src/p6_variables/merge.rs`) and named by `crates/unlace-bandb-base/src/p6_variables/{libcnames,contextnames,stablenames}.rs`.

Main already has most of the original's merge logic, in cover form. What is missing is naming evidence (loop bounds, array bases, saved registers), a use-site guard on phi merges, a size cap on cross-base coalescing, and a per-candidate suppression record. Research only: nothing was built or run. Line numbers are `origin/master` for the original and `origin/main` for main.

## Notes on the ranking

- Rows 1 to 3 are the candidates for issues. Row 2 is a correctness item and row 3 a speed item; row 1 is a naming item that must stay behind an option.
- Row 4 is worth a small follow-up in the decomp audit path (`decomp_dbg`), but no issue is filed here because it overlaps #27 and #1129.
- Searches for duplicates before filing: `gh issue list -R coleleavitt/unlace` found nothing for loop-bound naming, the pointer/scalar guard, or a merge cap. #23 (names from callee parameters, fields and types) is closed and is a different feature. #20 (phiarm splits a loop counter at the exit) is open and is a related but separate bug.
