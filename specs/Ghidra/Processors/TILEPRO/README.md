# Tilera TILEPro (TILEPro32, TILEPro64, TILE64)

Native SLEIGH written for unlace (issue #98). Encodings come from the GNU
binutils TILEPro opcode table; semantics follow the instruction descriptions of
the TILEPro Instruction Set Architecture reference (Tilera UG120); the calling
convention is the one GCC's former `tilepro` port used.

`tilepro.slaspec` is generated by `tools/gen_tilepro_sleigh.py`. The generator
reads each instruction's per-pipe fixed bits and operand layout from the GNU
binutils TILEPro opcode table (`opcodes/tilepro-opc.c`, passed on its command
line) and emits SLEIGH patterns from them; the p-code for every mnemonic is
written in the generator itself. No text of the GPL table is in this directory.
Regenerate with:

```
python3 tools/gen_tilepro_sleigh.py <binutils>/opcodes/tilepro-opc.c \
    > specs/Ghidra/Processors/TILEPRO/data/languages/tilepro.slaspec
```

Language: `TILEPRO:LE:32:default` (Linux ABI: arguments in r0-r9 then the stack
above an 8-byte caller frame area, result in r0 or r1:r0, return address in lr
(r55), r30-r52, tp and sp callee-saved, r63 reads as zero).

## What is modelled

- The 64-bit bundle: X mode (two slots, X0 and X1) when bit 63 is clear, Y mode
  (three slots, Y0, Y1 and the memory slot Y2) when it is set. Every encoding
  binutils knows decodes in every pipe it is valid in.
- Parallel bundle semantics: each slot computes into a per-slot temporary and
  the register writes are committed after all slots have read their sources, so
  `{ move r0, r1 ; move r1, r0 }` swaps. Control transfer (X1 or Y1) is
  emitted last.
- 32-bit integer ALU: add/sub, `addli`/`auli`, logic, compares (`seq` ..
  `slte_u`), `s1a`-`s3a`, shifts and rotates, `mnz`/`mz`/`mvnz`/`mvz`,
  `mm` (masked merge with wrapping start/end), `clz`/`ctz`/`pcnt`/`bytex`,
  `tblidxb0-3`, every 16x16 `mul*` and `mul*a` (accumulate) form, `lnk`.
- Loads and stores of every width with sign or zero extension, the aligned
  `lw_na` forms, the post-increment `*add` forms (two register writes), `tns`.
- Branches on a register (`bz` .. `bbns` and the predict-taken `t` forms),
  `j`/`jal` (`jf`/`jb`/`jalf`/`jalb` are the same encodings and decode under
  the `j`/`jal` names, as binutils prints them), `jr`/`jrp` (a return when the
  target is lr), `jalr`/`jalrp`.
- The `.sn` forms (and `movelis`, `addlis`) also write their result to `sn`.

## Gaps

- 98 named user operations: the SIMD byte/halfword lanes (`addb`, `seqh`,
  `maxb_u`, `mnzb`, ...), saturating adds and subtracts, averages and SAD,
  packing and interleaving, the shifted-accumulate `mul*sa` forms, `crc32_*`,
  `bitx`, `dword_align`, `mfspr`/`mtspr` (SPRs are numbers, not storage) and the
  cache, TLB, interrupt and system instructions (`swint1` is `syscall`).
- The network registers r56-r62 (sn, idn0-1, udn0-3) are plain registers; reads
  and writes do not model queue pops and pushes. The static-network processor's
  own instruction set is not decoded.
- `prefetch`, `info`, `infol`, `nop` and `fnop` are no-ops.

## Check

Every one of 19,785 random bundles that `tilepro-linux-gnu-objdump` (binutils
2.45) decodes, decodes here to the same mnemonics and operands in the same slots
(objdump leaves out `fnop` slots). The test image
`crates/unlace-cli/tests/fixtures/tilepro/sum_swap_call.bin` is the `.text` of
`sum_swap_call.s` assembled with `tilepro-linux-gnu-as` and linked at 0x10000.
