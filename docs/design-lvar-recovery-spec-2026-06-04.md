ROOT-CAUSE SPEC for coordinated DWARF local/param offset calibration. Tree left clean (git status empty), build green.

== CORE MEASURED FACT (the bug) ==
apply_dwarf_to_ssa (pipeline.rs:2306) seeds ssa.dwarf_local_names keyed by the RAW DW_OP_fbreg / DW_AT_frame_base=DW_OP_call_frame_cfa offset. On x86-64 SysV frame-pointer functions CFA = RBP+16, so DWARF offsets are 16 bytes more negative than the offsets the decompiler actually resolves stack accesses to. Confirmed in debug_cpp_rtti:main via UNLACE_STACK_FRAME_TRACE + readelf:
  - DWARF: d @ fbreg -56, c @ fbreg -48.
  - Real resolved accesses (StackVarRecoveryPass hint values, == frame slots): -40, -32, -24, -8.
  - i.e. true mapping rbp = cfa + 16: d -> -40, c -> -32. Exactly the +16 the task states.
So dwarf_local_names entries at -56/-48 never coincide with any real access offset; the names are dead, and seed_debug_stack_locals (stack_frame_recovery.rs:450) injects PHANTOM (offset,width) observations at -56 and -48 that no instruction touches. Those phantoms extend the array-detect run: -56,-48,-40,-32,-24 become five contiguous 8-byte slots -> detect_arrays fires array-group start=-56 span=40 -> the printer emits a single bogus "char d[40]" absorbing both objects. The 412 "local-decl excess" is exactly this class: unmatched DWARF names leave the real slots to be emitted as generic vN/v_NN/buf_NN decls, each counted as local_names.add_reported(1)+local_types.add_reported(1) (type_recovery_report.rs:2637-2649), inflating the precision denominator (precision = recovered / max(reported,recovered), precision_denominator() line 78-80).

== (1) type_stack_o2 "cc failed" — EXACT broken lines ==
Applied a temporary uniform +16 shift to dwarf_local_names only (NOT composite_var_types). Rebuilt; semantic-report -> passed=32 failed=1. Preserved source via UNLACE_SEMANTIC_KEEP_TEMPS and compiled with the harness flags (cc -std=c99 -Wall -Werror ...). The two fatal lines:
  type_stack_o2.c:136: error: assignment to 'void *' from '__int64' makes pointer from integer without a cast [-Wint-conversion]   ->   values = result;
  type_stack_o2.c:137: same error                                                                                                  ->   result = 0xb00000007ULL; p = result;
With the shift, the DWARF names "p" (struct Pair) and "values" (int[3]) finally land on the real slots, so the decls become "void * p; void * values;" (their inferred type is Ptr, because type recovery saw &p/&values passed to pair_score/array_mix). The DWARF struct/array TYPE was NOT moved with the name, so it does not override the Ptr decl. The initializer stores integer constants (the struct/array field writes that previously printed as *(_QWORD*)(p+24)=... now collapse to scalar assignments to a pointer-typed var). Hence int-to-pointer assignment = -Werror. ROOT: name relocation without coordinated TYPE relocation produces a named-but-mistyped pointer local; the buffer/struct that used to absorb the field writes is gone, exposing the type mismatch.

== (2) composite_var_types decoupling — exact mechanism + minimal fix ==
How a stack local gets a struct/array type: apply_dwarf_to_ssa, for each DWARF local with a type_name, calls stack_bases_for_frame_offset(ssa, frame_offset) (pipeline.rs:2415) which scans ssa.var_map for SsaVarnodes with base.space==Stack AND stack_offset_matches(base.offset, frame_offset) (line 2426: raw==frame_offset OR raw==abs(frame_offset)). For every matching varnode it inserts the lowered Type::Struct/Type::Array into ssa.composite_var_types (keyed by SsaVarnode). That map flows SSA -> structurer.rs:414 -> HIR.composite_var_types -> c_printer ctx (used by try_struct_field_access at c_printer.rs:3309-3359 for p->field recovery, NOT for the decl type itself).
The decoupling: stack_bases_for_frame_offset is matched against the SAME (unshifted) frame_offset. apply_dwarf_to_ssa runs at SSA-build time (lift_and_run_passes line 2749) BEFORE pipeline_stage_structural (line 1687) populates stack_offset_hints — so at seed time the only varnode offsets available are the raw lifter offsets. If you shift the NAME key (-56 -> -40) but leave stack_bases_for_frame_offset matching on the raw -56, no varnode matches the real slot, so composite_var_types stays empty for that slot. The decl then falls back to the type-inference Ptr (-> "void * p"). That is precisely why type_stack_o2 broke and why debug_cpp_rtti baseline shows "long c" cases (struct type lost).
MINIMAL FIX: compute ONE calibrated offset per DWARF local and use it for BOTH dwarf_local_names AND the stack_bases_for_frame_offset lookup (and the phantom-observation seed). Two viable shift sources, in order of robustness:
  (a) Empirical calibration (preferred, zero-assumption): after StackVarRecoveryPass fills stack_offset_hints, build the set S = {resolved offsets}. For the candidate uniform deltas {0, +16} (frame-pointer vs no-FP; could be generalized), pick the delta d such that the count of (dwarf_offset + d) values present in S (or in the set of frame.locals keys / stack_vars keys) is maximized. Apply d uniformly to every DWARF local AND param of that function. This auto-detects +16 only for FP functions and 0 otherwise, and never shifts a function whose accesses don't corroborate the shift (guards type_stack_o2's other funcs, debug_calls, etc).
  (b) Architectural constant: if ssa.arch==X86_64 AND the function has a frame pointer (saved RBP in frame_setup / RBP-based addressing), CFA=RBP+16 -> d=+16; else d=0. Simpler but more brittle for leaf/no-FP funcs.
Because apply_dwarf_to_ssa runs before stack_offset_hints exist, the calibration must move: either (i) re-run/refresh the DWARF seed in pipeline_stage_structural AFTER StackVarRecoveryPass and BEFORE recover_stack_frame (the task's suggested insertion point), or (ii) keep the raw seed but add a calibration step there that rewrites ssa.dwarf_local_names keys (and re-derives composite_var_types via stack_bases_for_frame_offset using the now-populated var_map) using the empirical delta. Approach (ii) inserted between line 2156 (StackVarRecoveryPass) and 2157 (recover_stack_frame) is the smallest blast radius. CRUCIAL: also pass the calibrated offset to seed_debug_stack_locals so phantom observations land on real slots (or, better, drop phantom seeding entirely when the name now coincides with a real observed offset — see fusion guard below).

== (3) C++ object typing — why "char d[40]" not "Cat c; Dog d;" ==
debug_cpp_rtti:main has Dog d @ fbreg -56 and Cat c @ fbreg -48 (each a 16-byte vtable-ptr object). True slots: d@-40, c@-32. Two compounding failures:
  (i) Offset mismatch (above): names -56/-48 never match real slots -40/-32, so neither name nor type attaches; AND the phantom -56/-48 seeds extend the array run to span 40 -> detect_arrays collapses everything into one slot, printed as "char d[40]" (named after the lowest DWARF local d, fallback buffer naming).
  (ii) Even with names calibrated, the struct TYPE must attach for the decl to read "Dog d;"/"Cat c;". Today the decl type comes from StackLvarAnnotation.c_type (stack_lvar_annotations_from_ssa, c_printer.rs:625-654), which is derived only from lv.ty (a flat TypeKind via stack_lvar_type_name) — it CANNOT express a named struct. composite_var_types CAN (it carries Type::Struct{name:"Dog",...}) but it is consumed only for p->field access, never for the local decl. So Cat/Dog would need to attach at the DECL emitter: emit_stack_frame_decls (c_printer.rs:7456) / compute_stack_frame_names (6430) must consult composite_var_types (or a new offset->Type side-channel) for the named struct type, OR stack_lvar_type_name must be extended to render Type::Struct names. Is it in scope? The data is available (dwarf.structs has Cat/Dog with byte_size; dwarf_base_type_to_ssa at pipeline.rs:2451 already lowers "struct Cat" to Type::Struct). The plumbing gap is purely: (a) calibrate the offset so the type attaches to the real slot, and (b) teach the decl emitter to print a named-struct/array decl from composite_var_types keyed by that slot. Both are local printer/pipeline edits, no new type infrastructure required.

Params are home-slot spills in -O0 prologues and are a major source of the 412 excess; they need the same calibration + naming path. (No behavior change yet; additive field.)
Step B. crates/unlace-cli/src/pipeline.rs, pipeline_stage_structural (line 2152): insert a new calibration fn between StackVarRecoveryPass (2156) and recover_stack_frame (2157). It (1) collects observed offsets O = distinct values of ssa.stack_offset_hints plus keys of any already-detected stack_vars; (2) for delta in {0, ptr*2 (=16 on x86_64 FP)} chooses the delta maximizing |{ raw+delta in O }| over all DWARF local+param raw offsets (require a strict majority / >=2 corroborated to accept a nonzero delta, else delta=0 — guards no-FP and tiny frames); (3) rewrites ssa.dwarf_local_names to the calibrated keys; (4) re-derives composite_var_types by calling stack_bases_for_frame_offset(ssa, calibrated_offset) (var_map is now populated) for every DWARF local/param that has a type, inserting Type::Struct/Array/Ptr. Keep apply_dwarf_to_ssa's raw name seed (or make it deferred) — simplest is: stop seeding composite_var_types in apply_dwarf_to_ssa (it's premature; var_map offsets aren't final), and do ALL DWARF-offset-dependent seeding in the new calibrated step.
Step C. crates/unlace-passes/src/stack_frame_recovery.rs, seed_debug_stack_locals (line 450): guard the phantom-observation injection. Only record a debug observation when the calibrated offset is NOT already corroborated by a real access at a nearby offset, OR drop phantom seeding entirely for offsets that coincide with an existing observation. This kills the -56/-48 phantoms that drive the bogus array-group. Also add a fusion guard in detect_arrays / the array-group sweep (lines 263-292, 491-530): do NOT fuse slots that carry DISTINCT dwarf_local_names (a,b,c,e are named scalars, not array elements) — check func.dwarf_local_names for the calibrated offsets in the run and bail if >1 distinct name. This directly prevents the "char e[12]" regression the project doc warns about.
Step D. crates/unlace-output/src/c_printer.rs: (i) compute_dwarf_locals (line 6366) currently does its OWN frame_size+frame_off translation (rsp_off = frame_size + frame_off) independent of the pipeline — this is a SECOND, divergent offset map. Reconcile it: prefer ssa.dwarf_local_names (now calibrated) over recomputing, or at minimum apply the same calibration so the printer's name_overrides/dwarf_local_types land on the same Varnode::stack keys the body uses. (ii) Teach the decl emitter (emit_stack_frame_decls line 7456 + compute_stack_frame_names line 6430) to render a named struct/array decl when ctx.composite_var_types has a Type::Struct/Array for the slot's base varnode (add a slot-offset->Type lookup, since composite_var_types is keyed by SsaVarnode). This produces "Dog d;"/"Cat c;"/"struct Pair p;"/"int values[3];" instead of char buffers or void* — and makes the type_stack_o2 assignments type-correct (struct/array field writes print as member/index stores, not scalar void* assignments).

== WHY PRIOR SERIAL ATTEMPTS EACH BROKE A DIFFERENT FIXTURE ==
They shifted ONE of the three coupled offset maps (dwarf_local_names key, composite_var_types lookup key, c_printer's frame_size+frame_off translation) or omitted the fusion/phantom guards. Any single-map shift desynchronizes name vs type vs decl, producing per-fixture failures (type_stack_o2 cc-fail from type desync; debug_cpp_rtti type loss; debug_calls bogus array from unguarded fusion). The fix MUST move all three together with a single empirically-validated per-function delta, plus the detect_arrays distinct-name guard and the phantom-seed guard.
