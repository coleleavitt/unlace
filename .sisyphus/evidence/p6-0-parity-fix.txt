P6-0: Macro-as-call extraction fix in scripts/measure_parity.py
================================================================

OBJECTIVE
---------
Exclude IDA-style byte/word/dword extraction macros, overflow/carry macros,
compiler builtins, _mm_* SIMD intrinsics, and C type-cast keywords from the
"calls" feature extracted by measure_parity.py. These were being counted as
function calls, polluting the Jaccard similarity score on the calls feature
(weight 3.0).

CHANGE
------
File: scripts/measure_parity.py (lines 70-95)
- BEFORE: keywords = {'if', 'for', 'while', 'switch', 'return', 'sizeof', 'typeof'}
          (7 entries)
- AFTER:  keywords set expanded to 63 entries covering:
          * 7 C keywords with parens
          * 26 IDA byte/word/dword extraction macros (LOBYTE, BYTE0-7, LOWORD,
            HIWORD, WORD0-3, LODWORD, HIDWORD, DWORD0-1, signed variants)
          * 10 IDA overflow/carry macros (__OFADD__, __OFSUB__, __SETP__,
            __SETO__, __SETS__, __SETZ__, __CFADD__, __CFSUB__, __SCFADD__,
            __SCFSUB__)
          * 10 compiler builtins (__builtin_*, __readfsqword, __readfsdword,
            __readgsqword, __rdtsc)
          * 4 C type-cast tokens (unsigned, signed, const, volatile)
- Plus prefix-based exclusions for _mm_*, _mm256_*, __builtin_* identifiers

WHY THE OVERALL PARITY DIDN'T JUMP +10-15%
------------------------------------------
The task hypothesis was that the macros only appeared on unlace's side and
their removal would directly improve Jaccard scores. Empirical investigation
shows the IDA reference decompilations ALSO contain these same macros (e.g.
IDA's call list for sub_1e2580 originally included 'BYTE1', 'LOBYTE',
'LODWORD'). Removing them from BOTH sides shrinks both the intersection and
the union proportionally, leaving the Jaccard ratio largely unchanged.

The dominant remaining source of Jaccard mismatch on calls is case
sensitivity: IDA emits `sub_1944B0` (uppercase hex) while unlace emits
`sub_1944b0` (lowercase hex). Per the task spec, fixing this is OUT OF SCOPE
for P6-0 ("Do NOT modify the feature extraction logic beyond the calls
exclusion"). Suggested follow-up task: add `.lower()` normalization in
score_call_overlap when comparing sub_<hex> identifiers.

The fix correctly implements the specified macro-exclusion logic. The
