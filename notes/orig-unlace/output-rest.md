# Original unlace: output formatters outside c_printer (archived master vs main)

Scope: `crates/unlace-output/src/` on `origin/master` (3aaf121866), excluding `c_printer/`, `cfg_dot.rs` and `windbg_dml.rs`: `expr_ast`, `demangle`, `cpp_stl`, `cpp_class`, `seh_output`, `instruction_annotations`, `semantic_diff`, `ir_dump`. Read first: `notes/archived-master-inventory.md` (rows A4, A6, A9, A10) and `notes/orig-unlace/ir-types.md` (row 18 covers `dump_lvars`, so it is not repeated here).

Corrections to the inventory: A10 says main has a partial hint mechanism in `crates/unlace-cli/src/assertdecl.rs`. That file is the `--assert` text syntax for the override plane, not automatic hints, so A10 is **missing**. A4 is right that nothing calls `semantic_diff`. Its doc says Myers, but the code is a whitespace-normalised LCS (`semantic_diff.rs:103-131`). On master, `cpp_class`, `instruction_annotations` and `seh_output` sit behind the `unwired` feature (`crates/unlace-output/src/lib.rs:5-38`), so they are not compiled into the default build. `cpp_stl` is wired (`c_printer/mod.rs:2543`). Main has no `unlace-output` crate; its emitter is `crates/unlace-emit/src/p9_emit/`.

Status values: **have** = same behaviour on main; **partial** = some of it, with the gap named; **missing** = not found by grep of the stated paths, with the paths searched noted. Each row cites code read on both refs.
