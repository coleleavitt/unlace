# Hex-Rays microcode, deep pass: what the optimizer and the microcode engine do that unlace lacks (2026-11-24)

Scope: the microcode layer of Hex-Rays 9.5, mined from `~/SiteResearch/ida-pro/hexx64.sqlite`
(strings, names, xrefs, pseudocode, read-only). `hexarm.sqlite` carries the same strings
(same core), so each finding below is checked in the x64 DB and the ARM DB is cited only as
corroboration. No decompiled body is pasted; IDA functions are named by address.

This note extends [`hexrays-microcode.md`](hexrays-microcode.md) (engine rows 1-19) and
[`notes/ida-hexrays-rules.md`](../ida-hexrays-rules.md) (named rules, `sub_18xxxx` family) and
[`notes/ida-unmerge.md`](../ida-unmerge.md). It does not repeat them; where they already cover an
item, section 2 says so.

Method. Strings: `strings` table, key words (`optimiz`, `glb`, `lvar`, `propagat`, `cse`,
`locator`, `kreg`). Call sites: `xrefs` from the string address into `functions`. Option
text: the option-dialog strings (`Hex-Rays Decompiler Options 1`, string 5200480) give the user-facing
meaning of each option key. unlace side: `rg` over origin/main `406b521b6f` (`crates/`, `docs/`,
`phases.toml`), file:line below from that commit. "Not found" means no rule, option or type with that
behaviour turned up in those greps; it is not a proof of absence.

Status: **have** / **partial** / **missing** / **ours-better**.

## 2. Checked and already covered (status corrected here)

These were listed as gaps in the earlier notes or came up in this pass. The evidence says they are covered.

- **MBA simplification.** IDA's microcode has no mixed-boolean-arithmetic solver in the strings: `mba.*` (5098315-5099643) are the fields of `mba_t`, the microcode array, not a solver. Its rules are pattern rules (`sub_18xxxx` and `SIMPLE-*`/`EXPR-*` families, `notes/ida-hexrays-rules.md`). unlace has an e-graph equality-saturation pass for MBA trees (`crates/unlace-bandb-base/src/p3_dataflow/egraph.rs:1`), **default off** (`crates/unlace-decomp/phases.toml:5956`). Status: **have, opt-in**, ours-better on the MBA class.
- **Mask and branch folds by value ranges.** IDA's options `optimize_m_and_instructions_using_value_ranges` (5142800) and `optimize_conditional_jumps_using_value_ranges` (5142736) and the warnings "masking with 0x%llX was optimized away" (5133800) and "conditional instruction was optimized away" (5133488). unlace's `rangefold` (`crates/unlace-decomp/phases.toml:1786-1797`) folds a comparison and an `& (2^k - 1)` mask whose outcome the dominating ranges fix. Status: **have**, narrower in the mask class (only `2^k - 1`).
- **Jump tables.** `simplified jtbl %d` (5104058) in `sub_1E78A0` is the jump-table index simplification, covered by the "jumptable" action set (`crates/unlace-decomp/src/infra/decompile_drive.rs:1493`) and `switchguardbound` (`phases.toml:2954`). The switch-size limit IDA names `limit_switch_ncases_for_optimization` (5142864) is `jumptablemax` (`phases.toml:4733`). Status: **have**.
- **Du/ud chains.** `sub_122480` builds a "du/ud chains" object (string 5100414); `sub_126B10` runs it twice, labelled "du-ud chains" and "stkvar du-ud" (5100440), with operand selectors 10 and 76. `failed to widen chains` (5109972) is IDA's limit on the chain set. unlace uses the SSA descendant structure instead, so there is no separate chain build to widen. Status: **have by design** (not separately verified in this pass).
- **Call arguments.** "combined partial callarg" (`sub_1071A0`) and "stkargs propagated" (`sub_4DA730`, `sub_43C320`) are covered by `calleearitylive` (`crates/unlace-bandb/src/p4_calls/calleearitylive.rs:1`, extends a partial argument list), `calleestackargs` and `callsitestackargs` (`crates/unlace-bandb-base/src/p4_calls/`). Status: **have**.
- **Purged bytes.** Strings 5131888 ("odd caller purged bytes") and 5132296 ("inconsistent function type and number of purged bytes") are covered by `calleepurge.rs` and `calleeretpurge.rs` in `crates/unlace-bandb-base/src/p4_calls/`. Status: **have**.
- **Unmerge and identical blocks.** `UNMERGE_CALLS` (`sub_191D80`), `REMOVE_IDENTICAL_JX` (`sub_18A300`), `OPTIMIZE_IDENTICAL_BLOCKS` (`sub_18D3A0`), `EXTRACT_IDENTICAL_HEAD_IF_INSNS` (`sub_18CF30`): covered by `notes/ida-unmerge.md`, `notes/ida-hexrays-rules.md` and `armhoist`/`dedupitetail`. Status: **have or partial as in those notes**.
- **Maturity ladder.** `sub_45D940` is only the printer for the dump header (`"%s %s:%d.%d"`) and the `MMAT_*` names; the ladder runs in `sub_45F420`, `sub_45FCA0` and `sub_460AC0`, which reference `MMAT_GLBOPT1-3`, `MMAT_LOCOPT`, `MMAT_PREOPTIMIZED` and `MMAT_LVARS` (xrefs). The existing row 1 says the same.
- **Preoptimization.** `sub_14F5A0` runs, in order: the "before preoptimize" dump, a per-block optimizer pass `sub_E7F30` with flag 1, "after first preoptimize", a second per-block pass with flag 0, `sub_D7DA0`, `sub_D8130`, a set of mba flag bit `0x200`, "after second preoptimize", then `sub_4A2D60` (combined operand propagation), then `sub_3C3A40` and, when that returns 0, `sub_3B0000`. Status: **have** (rule pools with restarts; the structure is in `hexrays-microcode.md` row 2).
- **Special microcode locations.** `sub_1D3D10` sets a table of names for the special locations the dumps and global passes use: `LVARS`, `GLBLOW`, `GLBHIGH`, `sp`, `RET`/`retaddr`, `SHADOW`/`shadow`, `ARGS`/`arg`. unlace has no direct equivalent to name; the role of `GLBLOW`/`GLBHIGH` in the global passes is not decoded here.

## 3. Not decoded in this pass

- `sub_4B56B0` (straighten, row 3), `sub_1F7B90` (kreg, row 4), `sub_346180` (duplicate locators, row 7): the body was read only at the call and string level.
- The rewrite site for union comparisons (row 8), the sign-bit rule (row 9), the address-comparison rule (row 2) and the constant byte-swap fold (row 10): their option keys and text are known, the rule function is not located. Searching the pseudocode for the option keys and warning texts: no function mentions the address-comparison key, the sign-bit key or the union-comparison text. `fold_constant_byteswap` appears only in the option reader `sub_3C1FF0`.
- `sub_19EA00` ("propagate step %d result (propagated %d)", 70 KB) and `sub_1A33E0` ("global propagate result", 26 KB): the propagation loop with a step counter. unlace's rule pools (`hexrays-microcode.md` row 2) cover the behaviour; the step bound was not compared.
- `hexarm.sqlite` was checked for the same strings (each present once or more), not decoded.
