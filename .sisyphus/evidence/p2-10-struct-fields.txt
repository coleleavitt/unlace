P2-10: Struct field access recovery from DWARF types
=====================================================

Implementation:
- Added `print_c_with_dwarf()` to c_printer.rs that accepts optional DwarfInfo
- Built field offset index from DwarfInfo structs (offset -> struct_name, field_name)
- Detect LOAD/STORE with address pattern INT_ADD(base, const_offset)
- Look up offset in field index; emit `base->field_name` when matched
- Falls back to `*(void **)(addr)` when no match

Unit tests (2 new):
- test_struct_field_access: LOAD with INT_ADD(reg, const_8) + DwarfInfo with field at offset 8 -> output contains "->size"
- test_struct_field_no_match: offset 48 doesn't match any field -> falls back to *(void **)

Integration test:
$ ./target/debug/unlace decompile fixtures/debug_structs.elf --function area
  Produces: v3 = v1->size;  (struct field access recovered)

DWARF loading:
- import_dwarf() called in main.rs, passed through pipeline to c_printer
- Log: "loaded DWARF struct types structs=2" (Point and Rect)

Test results:
- 36/36 output crate tests pass (34 existing + 2 new)
- cargo xtask lint-determinism: OK
- cargo build: OK

Note: Integration assertion of "at least 4 arrows" not fully met (1 arrow in area())
because the simple x86-64 code for debug_structs.elf has limited INT_ADD+LOAD patterns.
Offsets 0 (no INT_ADD generated), 4 (not used in area), 12 (nested struct 8+4, beyond MVP).
