P2-1: Fix SSA version bug in C printer
=======================================

Bug: The C printer hardcoded `version: 0` for all SSA varnodes in 4 places:
- collect_varnodes output (line ~114)
- collect_varnodes inputs (line ~122)
- emit_statement output (line ~327)
- emit_operand inputs (line ~603)

This caused different SSA versions of the same base varnode to collapse into
a single C variable name. Example: three assignments to register 0 all
produced `v1 = ...` instead of `v1 = ...; v2 = ...; v3 = ...`.

Fix: Added SSA version tracking to PrintCtx with two-pass design:
1. collect_varnodes: Maintains ssa_next_version and ssa_current maps per base
   Varnode. Each Statement output gets the next version; each Statement input
   reads the current (most recently assigned) version. Pre-computed results are
   stored in stmt_outputs and stmt_inputs maps keyed by walk-order index.
2. emit_statement/emit_expr/emit_operand_resolved: Look up the pre-computed
   SsaVarnode for each statement via a matching emit_stmt counter that walks
   in the same order as collect_varnodes.

New test: test_ssa_version_names
- Creates 3 statements writing to register 0 at addresses 0x1000, 0x1004, 0x1008
- Asserts at least 3 distinct variable declarations
- Asserts all 3 assignment LHS names are distinct
- Asserts the second statement reads the first's output (not its own)

Test results:
- cargo test -p unlace-output: 32 passed (31 existing + 1 new), 0 failed
- cargo test --workspace: all tests pass (650+), 0 failed
- cargo xtask lint-determinism: OK (BTreeMap only, no HashMap)
