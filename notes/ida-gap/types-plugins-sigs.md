# IDA 9.5 type and naming knowledge vs unlace: TIL, FLIRT, Lumina, RTTI, ObjC, Swift/Go/Rust, PDB/DWARF, struct recovery (2026-11-24)

Area survey for the IDA technique gap track, area *types-plugins-sigs*. It extends `notes/ida-gaps.md`,
`notes/ida-module-survey.md` §3.3, `notes/ida-typelib-pe.md`, `notes/ida-pdb.md` and
`notes/ida-apple-mechanisms.md`, and does not repeat rows those notes close. Where the 2026-11-22 survey
says "NONE" and the tree now has the feature, this note says so and cites the code.

Method. IDA side: `~/SiteResearch/ida-pro/derived/ida-links.sqlite` (`string_users`, `api_use`), the
module dumps in `~/SiteResearch/ida-pro/sqlite/<cat>__<module>.sqlite` (`pseudocode` by `ea`) and
`ida-9.5-tils.sqlite` (154 shipped .til files, 3,076,800 types, 9,073,972 symbols). Function names are the
dump's `sub_<ea>`. unlace side: `codegraph query` on `origin/main` at survey time; file:line is the
`nodes.start_line` or `calls.line` it reported. Status: have, partial, missing, ours-better. Size: S < 1
PR-day, M = a few PRs, L = a track.

```sh
D=~/SiteResearch/ida-pro/derived/ida-links.sqlite
sqlite3 -readonly $D "select func_name,text from string_users where mod='libida' and text like '%startup signature%'"
sqlite3 -readonly ~/SiteResearch/ida-pro/ida-9.5-tils.sqlite "select file,type_count,symbol_count from tils where file like '%gnulnx%'"
codegraph query "SELECT caller, caller_file, line FROM calls WHERE callee = 'til_choice'"
```

## Top 10 (ranked by impact × evidence ÷ size)

1. **DWZ supplementary files** (row 13, S-M). Distro debug packages are DWZ-compressed, and unlace already reads the companion's DWARF, so this is the one missing step between "debuginfo installed" and full types on Fedora/Debian binaries. IDA: dwarf `sub_B7E40`, `sub_2B4B0`.
2. **Type libraries for Mach-O and non-x86 Linux** (row 1, S). `til_choice` returns nothing outside Windows (`typelib.rs:483`), while IDA ships 34k-type macOS and 20k-type iOS SDK libraries and `gnulnx`/`android` libraries for ARM and PPC. The reader (`til.rs:1531` `to_typelib`) already decodes them.
3. **FLIRT startup selection** (row 2, M). Startup signatures are rejected today (`flirt/mod.rs:150`). Using them would turn `flirt` from "list the right .sig files" into "point at IDA's sig directory".
4. **Struct copies as assignments** (row 16, S). This is Hex-Rays `sub_4C8BB0` and is purely a readability rule. The types it needs are what `structsynth` and `libctypes` already produce.
5. **Swift value witness functions** (row 9, S-M). 5.6% of the functions in the measured iOS app are VWT entries without a name or prototype (apple note #4).
6. **Static libc recognition shipped by default** (row 3, M). FID databases for static musl/glibc, so that static binaries name their libc without any IDA input.
7. **`pdbtypes` default** (row 12, S). The code is done (#30), only the measurement is missing.
8. **Struct synthesis defaults** (row 15, S). `structmerge`, `structheadless` and `fieldtype` are opt-in and have no `docs/features/<slug>/` record. Measure them with `typescore`/`structscore`, then decide.
9. **`dwarfglobaltypes` default** (row 13 neighbour, S). DWARF globals are named but not typed by default. Measure on the DecBench unstripped twins.
10. **Bionic detection for `android_*` libraries** (part of row 1, S). Choose `android_arm64.til` over `gnulnx_arm64.til` when the dynamic section names `libc.so` with Bionic's `LIBC` version, which matters for every Android `.so` decompiled from an APK.

Not gaps: Lumina auto-pull (the decompiler never uses the network, by decision), ordinal names, MSVC and Itanium
RTTI typing, Go and Rust helpers, ObjC metadata. These are at parity or ahead.
