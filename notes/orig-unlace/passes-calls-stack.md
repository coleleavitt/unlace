# Original unlace: calling-convention and stack-frame techniques

Scope: `origin/master` `crates/unlace-passes/src/calling_convention.rs` and `stack_frame_recovery.rs`, compared against `origin/main` by reading the main code (not its STUB comments). Main has no `calling_convention` or `stack_frame_recovery` module; the same jobs are done in `crates/unlace-bandb-core` (p3 dataflow, p4 calls, p6 variables) and `crates/unlace-middle`. The archived pass header notes that the principled parameter test (live-on-entry) was never wired on master either.

Status: **have** = main does it, **partial** = main does a narrower or different version, **missing** = no equivalent found. Ranked: items 1 to 8 are ports, items 9 to 15 are already on main and listed so nobody re-audits them.
