P11-18 Investigation (debug_calls if-recovery):
------------------------------------------------
Finding: debug_calls.elf functions use cmov instructions (cmovns, cmovge,
cmovle) which are branchless conditional moves. The Ghidra/sleigh pcode
lifts these as single-block COPY operations without CBRANCH. IDA recovers
cmov as if-statements via a dedicated cmov-to-if idiom pass.

Functions affected:
  - abs_val: uses cmovns (branchless abs)
  - max: uses cmovge (branchless max)
  - min: uses cmovle (branchless min)

Root cause: Missing cmov-to-if recovery pass. This is a feature request,
not a structuring bug. The lifter correctly represents the branchless
semantics; recovering if-statements requires detecting the cmov pattern
in pcode and splitting the block into a diamond CFG.

Target NOT MET (0 ifs, target was ≥2). Evidence-only.

P11-20 Investigation (cpp_rtti goto elimination):
--------------------------------------------------
Finding: cpp_rtti's identify() function has 2 gotos from genuinely
irreducible cross-branch control flow. The CFG has:
  - BB_0 → BB_5 (null check) or BB_1
  - BB_1 → BB_2 (dynamic_cast succeeded) or BB_4 (try second cast)
  - BB_2 → BB_3 (vtable match) or BB_6 (join)
  - BB_4 → BB_6 (join from second cast path)
  - BB_5 → BB_6 (join from null path)

BB_5 and BB_6 are join points with 2+ predecessors containing MULTIEQUAL
(phi) nodes. The gotos are cross-branch jumps from one if-else arm into
a sibling arm's label. The forward-goto-elim pass cannot handle labels
inside nested scopes.

Wave 1 passes (goto-to-break, goto-to-continue, while-break-to-if,
forward-goto-elim, tail duplication, return merge) did NOT resolve these
gotos because:
  1. The gotos are not inside loops (goto-to-break/continue don't apply)
  2. The labels are inside nested if-else scopes (forward-goto-elim can't reach)
  3. The join blocks have many MULTIEQUAL nodes (tail duplication threshold exceeded)
