# Original unlace: algebraic and condition simplification

Scope: `origin/master` `crates/unlace-passes/src/algebraic_simplify.rs` (2409 lines) and `condition_simplify.rs` (2161 lines), compared with main's Ghidra-style rule pools: `crates/unlace-bandb/src/p3_dataflow` (ruleaction_3, _5, _6), `crates/unlace-bandb-base/src/p3_dataflow` (ruleaction_2, _7, flagcompare, egraph, floatquiet, floatnegpiece) and `crates/unlace-bandb-core/src/p3_dataflow` (ruleaction_1, _4). Read statically at origin/main; nothing was built or run. "partial" and "unverified" mark places where the whole rule shape was not confirmed.

The original runs one SSA pass per file: each rule matches an IR op and returns a replacement (copy or rewrite in place), and a no-op check keeps the fixed point from churning. Main expresses the same rules as rule objects (`get_op_list` + `apply_op`), so most original rules have a direct counterpart. Only the float identities are absent outright.

## Notes for the candidate issues

- **Row 1, float sign of zero.** `x + 0.0` gives `+0.0` when `x` is `-0.0`, so the rewrite to `x` is not exact. The original excludes `-0.0` as the matched constant but still rewrites `x + (+0.0)`. Under CLAUDE.md's rule that a judgement call ships behind an option, this belongs behind one. `x * 1.0` and `x / 1.0` are exact apart from sNaN quieting, which main's floatquiet.rs already models.
- **Row 2, flag model.** `XOR(sless, sborrow)` equals `sless` only under the lifter's convention that the sign flag is `IntSless(a,b)`. Gate it on the flag model, not as a general identity.
- **Row 3, alias guard.** The original's bounded walk (16 COPY hops) stops an SP-adjust chain from re-folding into itself every fixed-point round. Any port should keep the bound and add a test that reproduces the drift.
- **Rows 4 and 5** need a confirming grep or test run before anyone opens an issue on them; they are listed as unverified.
- Not covered here: const_fold.rs and expression_tree.rs in origin/master, which are separate passes and were not compared, and the out-of-scope items (servers, debugger, emulator, LSP, hand-written lifters).
