# C-SKY ABIv2 (CK801, CK802, CK803, CK804, CK805, CK807, CK810, CK860)

Native SLEIGH written for unlace (issue #98). Encodings follow the GNU binutils
C-SKY opcode table (`opcodes/csky-opc.h`, read for encoding facts only; no table
text is in this directory) and were checked against `csky-elf-objdump`;
semantics follow the C-SKY V2 instruction set manual. The calling convention is
the C-SKY ABIv2 one GCC and LLVM use.

Languages (each `.slaspec` includes `csky.sinc` with a set of `@define`s):

| Language | Cores | Extensions | File |
|---|---|---|---|
| `CSKY:LE:32:v2` | CK801-CK810 | FPUv2, DSP, DSP-enhance | `csky_le.slaspec` |
| `CSKY:BE:32:v2` | CK801-CK810, big endian | FPUv2, DSP, DSP-enhance | `csky_be.slaspec` |
| `CSKY:LE:32:ck810v` | CK810v | FPUv2, VDSP (v1), DSP, DSP-enhance | `csky_810v.slaspec` |
| `CSKY:LE:32:ck860` | CK860 | FPUv3, DSP, DSP-enhance | `csky_860.slaspec` |
| `CSKY:LE:32:v1`, `CSKY:BE:32:v1` | CK510, CK610 (ABIv1) | coprocessor interface, CK610 DSP multiplies | `csky_v1_le.slaspec`, `csky_v1_be.slaspec` (`csky_v1.sinc`, `csky_v1.cspec`) |

One integer decoder serves every ABIv2 core: CK801 code uses the 16-bit set and a
few 32-bit instructions, CK802-CK860 add the rest. FPUv2 and FPUv3 reuse the same
opcode space with different meanings (`0xf4001c00` is `fmovis` on FPUv2 and
`fhtosi.rn` on FPUv3), so they are separate languages.

ABI: arguments in r0-r3 then the stack, result in r0 or r1:r0, sp is r14, the
return address is r15 (lr), r4-r11, r16, r17 and r28 (gb) are callee-saved.

## What is modelled

- Instruction length: a halfword whose top two bits are 11 starts a 32-bit
  instruction, stored high halfword first (both byte orders).
- The 16-bit set: `br`/`bt`/`bf`, `lrw` and the extended `lrw` form, sp-relative
  `addi`/`subi`/`ld.w`/`st.w`, `push`/`pop` (`pop` returns through lr), the
  immediate, register and compare groups, shifts, extends, `jmp`/`jsr`/`rts`,
  `revb`/`revh`, `mult`/`mulsh`, byte/half/word loads and stores.
- The 32-bit integer set: three-register ALU, the C-flag compares, tests and
  `mvc`/`mvcv`, conditional `incf`/`inct`/`decf`/`dect`/`clrf`/`clrt`,
  `decgt`/`declt`/`decne`, shifts with carry (`lslc`, `lsrc`, `asrc`, `xsr`),
  `zext`/`sext`/`ins` bit fields, `ff0`/`ff1`, `brev`, `xtrb0-3`, `bgenr`,
  `bmaski`, `divu`/`divs`, `ixh`/`ixw`/`ixd`; loads and stores with a 12-bit
  offset (including `ld.d`/`st.d` pairs), register-indexed `ldr`/`str`, `ldm`/
  `stm`/`ldq`/`stq`; gb-relative `lrs`/`srs`/`addi rz, r28`, `grs`; `bsr`,
  compare-with-zero branches, `bnezad`, `jmpi`/`jsri` through the literal pool,
  `movi`/`movih`/`ori`/`lrw`; 32-bit `push`/`pop` with r4-r11, lr, r16-r22 and r28;
  `mul.u32`/`mul.s32`/`mula.*` (64-bit results in rz+1:rz), `divul`/`divsl`.
- The C flag is a register; carries, borrows (C is "no borrow"), compares and
  bit tests set it as the manual says.

- FPU and VDSP (`csky_fpuv2.sinc`, `csky_fpuv3.sinc`, `csky_vdsp.sinc`) are
  generated by `tools/gen_csky_ext_sleigh.py` from the binutils opcode table
  (opcode values and operand fields only; the p-code is written in the generator):
  `python3 tools/gen_csky_ext_sleigh.py <binutils>/opcodes/csky-opc.h
  specs/Ghidra/Processors/CSKY/data/languages`. Registers: `fr0`-`fr31` (64-bit;
  `fr0`-`fr15` are the low halves of the 128-bit `vr0`-`vr15`), `fcr`, `fesr`.
  Modelled as IEEE p-code: single and double add, subtract, multiply, divide, the
  four multiply-accumulate forms (and the fused FPUv3 ones), abs, neg, sqrt,
  reciprocal, compares into C (including against zero and unordered), int/float
  and single/double conversions with the four rounding modes, moves to and from
  general registers, loads and stores (offset and register-indexed), `flrw`
  literals, `fsel`, and the FPUv3 `fmovi` constants (decoded to their IEEE bit
  patterns). VDSP vector loads and stores (64-bit `d` and 128-bit `q` forms) and
  `vmov` are p-code.

- DSP (CK807/CK810, `csky_dsp.sinc`) and DSP-enhance (CK804/CK805, `csky_edsp.sinc`)
  are generated by the same tool and included in every ABIv2 language; they share
  no encodings with the integer set, the FPUs, VDSP or each other. p-code: the
  hi:lo multiply and multiply-accumulate forms (`mulu`, `muls`, `mulua`, `mulsa`,
  `mulus`, `mulss`, `mulsha`, `mulshs`), `mfhi`/`mflo`/`mthi`/`mtlo`, `max`/`min`
  (32-bit), and the post-increment loads and stores (`ldbi`/`stbi` by the access
  size, `ldbir`/`stbir` by a register).

- `bloop rx, start[, last]` (DSP-enhance) closes a zero-overhead loop: it sits after
  the body, its signed offsets point back to the first body instruction and to the
  last one (gas fills the second in when it is omitted). It is modelled as
  `rx = rx - 1; if (rx != 0) goto start;`, a real back edge, so the loop decompiles
  as a `do`/`while`. The hardware skips the `bloop` itself on later iterations; the
  p-code is the same loop.
- Java acceleration (CK802j): `jmpix rx, 16|24|32|40` is an indirect jump to
  `svbr + (rx & 0xff) * size` (`svbr` is a register; that the index is the low byte
  of rx is our reading of the Java bytecode dispatch it serves).
  `bpop.h`/`bpop.w`/`bpush.h`/`bpush.w` (the bytecode operand stack) and
  `bmset`/`bmclr` are named user operations.

## ABIv1 (CK510, CK610)

A separate 16-bit ISA in `csky_v1.sinc`, hand-written from the binutils
`csky_v1_opcodes` table (encodings) and the CK610 manual (semantics). r0 is the stack
pointer and r15 the link register. The ABI (`csky_v1.cspec`) passes arguments in
r2-r7 and returns in r2 (r3:r2 for 64-bit values).
- All of the E1 integer set: C-flag compares and tests, conditional
  `inct`/`incf`/`dect`/`decf`/`movt`/`movf`/`clrt`/`clrf`, the `dec*` counters,
  `xtrb0-3` into r1, `ff1`, `brev`, the extends, register and immediate shifts
  (including the carry forms and `xsr`), `divu`/`divs` by r1, `ixh`/`ixw`, `bmaski`
  (0 meaning 32), `ldm`/`stm` (rN-r15 from r0), `ldq`/`stq`, `lrw`/`jmpi`/`jsri`
  through the literal pool, and the 11-bit branches.
- The CK610 DSP `mulu`/`muls`/`mulsh` accumulate forms on hi:lo.
- `mfcr`/`mtcr`, `psrset`/`psrclr` and the coprocessor instructions are named
  user ops.
- Not decoded: the MP `ldex`/`stex` and the CK620 MAC `omflip`. They share
  encodings with each other and with the DSP set, and CK610 has neither.
- The CK610 floating point is reached through the coprocessor instructions, not
  separate encodings.

## Gaps

- 31 named user operations: control registers (`mfcr`/`mtcr` read and write
  `cr<n, bank>` as numbers, not storage), `psrset`/`psrclr`, `trap`, `rte`/`rfi`,
  `stop`/`wait`/`doze`, `sync`/`bar.*`/`idly`, cache and TLB maintenance,
  `ldex`/`stex` monitors, `nie`/`nir`/`ipush`/`ipop`, the coprocessor
  instructions (`cpop`, `cprgr`, ...), `mulsw`, `mulall.s16.s`.
- FPU and VDSP named user operations (19 FPUv2, 104 FPUv3, 354 VDSP): paired-single (`*m`, `.f32`)
  and half-precision arithmetic, `fmaxnm`/`fminnm`, `fins`, `fmovx`, fixed-point
  conversions, the register-list `fldm`/`fstm` forms, the FPUv2 `fmovis`/`fmovid`
  immediates, and every VDSP lane operation.
- DSP and DSP-enhance named user operations (12 DSP, 186 DSP-enhance): the
  SIMD byte/halfword lanes (`padd.8`, `pcmphs.u16`, ...), saturating and halving
  arithmetic, clipping, packing, the fractional and complex multiplies, `mulsw`/
  `vmul*`, `mfhis`/`mflos`. Results that the manual writes to a register pair
  are modelled as a single-register result.
- `ldm`/`stm` of 17 or more registers use a register-space loop instead of
  unrolled moves (an instruction can name only about 20 operands).
- Not decoded: VDSP2 (CK805, CK860v: binutils has no table for it, so there is no
  oracle).
- The compiler spec is the soft-float ABI (floating-point arguments in r0-r3);
  hard-float code that passes arguments in fr0-fr3 shows them as `fmtvr` moves.

## Check

`csky-elf-objdump` (binutils 2.45) is the oracle. Every random word it decodes
here decodes to the same mnemonic and operands, apart from a handful the linear
listing prints as data:
- integer: about 70,000 16-bit and 32-bit words, `-mcpu=ck860`, both byte orders;
- FPUv2: `ck807f`/`ck810f`, both byte orders;
- FPUv3: `ck860f`, about 13,000 valid words;
- VDSP: `ck810v`;
- DSP: `ck810`, `ck860`, `ck810v` (the `0xc4` group);
- DSP-enhance: `ck804e` (the `0xd0`, `0xd4`, `0xe8` and `0xf8` groups), both byte orders;
- Java: `ck802j`.
`fmovi`, `fmovis`/`fmovid` and `flrw` are compared by mnemonic, because objdump
prints the decoded float.

ABIv1: every random 16-bit word `csky-elf-objdump -mcpu=ck610e` decodes (about
27,000, both byte orders) decodes here the same, apart from words the listing
prints as data because a random `lrw` points at them.

Test images in `crates/unlace-cli/tests/fixtures/csky/` are the `.text` of the
`.s` files next to them, assembled with `csky-elf-as` (`-mcpu` as named in
`processors.toml`) and linked at 0x8000.
