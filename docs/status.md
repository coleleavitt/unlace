## Architecture support tiers

The four-tier classification comes from `unlace_ir::arch_support`:

- **production** — lifter, ABI/calling-convention recovery, and final C output
  exercised by golden fixtures and a non-trivial real-binary corpus. Use with
  confidence.
- **beta** — lifter is complete enough that simple programs lift cleanly, but
  parts of the pipeline (ABI, SIMD/FPU, structuring) are not at production
  parity. Expect rough edges.
- **fixture-only** — exercises only the fixture binaries we ship; no real-binary
  corpus evidence yet.
- **stub** — the crate exists with decoder skeleton; many opcodes intentionally
  emit `IrOp::Unimplemented`.

## CExpr (IDA `cot_*`) coverage

`CExpr` carries **36 explicit variants** out of the 69 `cot_*` opcodes IDA
defines. The remaining ~33 map cleanly through `Binary { op }`
token-based dispatch (arithmetic, comparisons, shifts, logical
connectives, integer compound-assignments). After completion plan §4
the explicit set includes structural leaves (Empty, Label, Var, Num,
Fnum, TypeRef, Str, Obj, FuncId, StmtExpr), unary forms (Neg,
LogicalNot, BitwiseNot, PreInc/Dec, PostInc/Dec, FloatNeg, Sizeof,
Cast, Coerce, Deref, AddrOf), composite forms (Member, Index, Call,
Helper, Macro, Ternary), assignments (Assign, CompoundAssign, Comma),
float arithmetic (FloatBinary), pointer arithmetic (PtrDiff), and the
generic Binary fall-through.

Authoritative table: `crates/unlace-output/src/COVERAGE.md`. Live
machine-readable source: `unlace_output::expr_ast::cexpr_coverage_rows`.

| Type/variable recovery accuracy | `cargo run -p xtask -- type-recovery-report` | `MEASURED fixtures=4 functions=17 recovered=73 expected=101 accuracy=72.3% source_known=20 dwarf_candidates=5` | First exact textual DWARF/source scorer; C++ templates/RTTI and non-host binaries are still explicit skips. |

`bash scripts/quality_axes.sh` runs all three reports without treating a known
XFAIL or skipped axis as solved. See
`docs/parity-quality-execution-plan-2026-05.md` for the active metric plan.

## What is currently NOT shipped

Items called out by the long-form roadmap that have not yet landed in
production form. Tracked so the README doesn't overclaim:

- FLIRT/SIG-driven library name recovery wired into the active CLI path.
- DWARF v5 split-DWARF (`.dwo`/`.dwp`) evaluator and full DW_OP location lists.
- PDB TPI/IPI stream walker.
- dyld shared cache extraction and kernel-cache filesets.
- Authenticode/SHA-2 signature verification on PE.
- Persistent `.unlace` project format with rename/comment/type round-trip.
- LSP/TUI/Web UI front-ends.
- Reproducible signed releases + SBOM publishing.
- Full semantic recompile-and-compare across the source-known fixture corpus.
  The current report covers 15 passing executable cases, 2 known failing host
  cases (optimized-main lvar/phi plus x86 subregister recovery), and 3
  non-host unsupported cases.
- Broad DWARF/source-ground-truth type and variable recovery accuracy metrics.
  The current report scores 4 C DWARF fixtures exactly and skips C++/non-host
  cases explicitly.

Adding any of these moves the related row in the matrices above; do not promote
items until the evidence exists.

## How to refresh

When a batch lands code that should move a row:

1. Update `crates/unlace-ir/src/arch_support.rs` (or the relevant module).
2. Run `RUSTC_WRAPPER= cargo test -p unlace-ir --lib arch_support`.
3. Regenerate the matrix in this file (the in-tree string is hand-mirrored
   today; the source-of-truth is the Rust table, which the unit test pins).
4. Update `docs/rebaseline-<date>.md` if the verification commands now report
   different totals.

The handoff for this batch lives at `docs/handoffs/BATCH27_HANDOFF.md`.
