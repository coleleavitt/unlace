# Tilera TILE-Gx (TILE-Gx8000 family)

Native SLEIGH written for unlace (issue #98). Encodings come from the GNU
binutils TILE-Gx opcode table; semantics follow the instruction descriptions of
the TILE-Gx Instruction Set Architecture reference (Tilera UG401); the calling
convention is the one GCC's former `tilegx` port used. The prior SLEIGH module
aleph-void/ghidra-tilegx has no license; it was not opened or copied.

`tilegx.slaspec` is generated by `tools/gen_tilegx_sleigh.py`. The generator
reads each instruction's per-pipe fixed bits and operand layout from the GNU
binutils TILE-Gx opcode table (`opcodes/tilegx-opc.c`, passed on its command
line) and emits SLEIGH patterns from them; the p-code for every mnemonic is
written in the generator itself. No text of the GPL table is in this directory.
Regenerate with:

```
python3 tools/gen_tilegx_sleigh.py <binutils>/opcodes/tilegx-opc.c \
    > specs/Ghidra/Processors/TILEGX/data/languages/tilegx.slaspec
```

Language: `TILEGX:LE:64:default` (Linux ABI: arguments in r0-r9 then the stack
above a 16-byte caller frame area, result in r0 or r1:r0, return address in lr
(r55), r30-r52, tp and sp callee-saved, r63 reads as zero).

## What is modelled

- The 64-bit bundle: X mode (two slots, X0 and X1) when bits 62-63 are zero,
  Y mode (three slots, Y0, Y1 and the memory slot Y2) otherwise. Every
  encoding binutils knows decodes in every pipe it is valid in (335 mnemonics).
- Parallel bundle semantics: each slot computes into a per-slot temporary and
  the register writes are committed after all slots have read their sources, so
  `{ move r0, r1 ; move r1, r0 }` swaps. Control transfer (X1 or Y1) is
  emitted last.
- Integer ALU, 32-bit (`*x`) forms with sign extension, compares, conditional
  moves (`cmoveqz`, `cmovnez`, `mz`, `mnz`), shifts and rotates,
  `shlNadd`, `shl16insli`, bit fields (`bfextu`, `bfexts`, `bfins`, `mm`,
  including wrapping fields), `clz`/`ctz`/`pcnt`/`revbytes`, all 16x16
  `mul_*`/`mula_*` forms, `mulx`/`mulax`, `tblidxb0-3`.
- Loads and stores of every width, sign and zero extension, the non-temporal
  and `ldna` forms and the post-increment `*_add` forms (two register writes).
- Atomics (`exch`, `cmpexch` against the `CMPEXCH_VALUE` register,
  `fetchadd`, `fetchaddgez`, `fetchand`, `fetchor`, 4- and 8-byte).
- Branches on a register (`beqz`..`blbs` and the predict-taken `t` forms),
  `j`/`jal`, `jr`/`jrp` (a return when the target is lr), `jalr`/`jalrp`,
  `lnk`.

## Gaps

- 151 named user operations: the SIMD `v1*`, `v2*`, `v4*` lanes, the complex
  multiplies (`cmul*`), the floating-point helper steps (`fsingle_*`,
  `fdouble_*`), `crc32_*`, `dblalign*`, `shufflebytes`, the saturating
  `addxsc`/`subxsc`, `revbits`, `mfspr`/`mtspr` (SPRs are numbers, not
  storage) and the cache, TLB, interrupt and system instructions (`swint1` is
  `syscall`).
- The network registers r56-r62 (sn, idn0-1, udn0-3) are plain registers; reads
  and writes do not model queue pops and pushes.
- `prefetch*`, `info`, `infol`, `nop` and `fnop` are no-ops. Aliases with
  identical encodings decode as the first binutils name (`prefetch` for
  `prefetch_l1`).
- Big-endian TILE-Gx and TILEPro (32-bit) are not covered.

## Decode check

Against `tilegx-linux-gnu-objdump` (binutils 2.45): 100,000 random 64-bit
words gave 58,692 bundles objdump decodes; all 58,692 decode to the same
slots, operands and branch targets (fnop/nop slots aside, which objdump omits),
and 300 of 300 sampled words objdump rejects are rejected here too.
