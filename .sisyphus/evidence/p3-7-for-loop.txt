P3-7 For-loop Recovery — Evidence
==================================

TASK: Detect canonical for-loop pattern (init + condition + update + body)
from existing while-loop structuring in crates/unlace-struct/src/structurer.rs.
Convert eligible while-loops into `for (init; cond; update) { body }`.

DELIVERABLES
============

1. New HirNode variant `For { init, cond, update, body }`
   File: crates/unlace-struct/src/hir.rs (lines 80-99)

2. Post-pass `recover_for_loops()` in structurer.rs
   File: crates/unlace-struct/src/structurer.rs (lines 922-1129)
   - Walks HIR tree post-structuring
   - Detects [Statement(init), While{cond, body}] pattern
   - Validates eligibility:
     * init defines a base varnode V (Copy/IntAdd/IntSub/IntZext/IntSext/Cast/Load)
     * cond.base == V
     * Last Statement in body is V = V op const (IntAdd/IntSub)
     * V is not referenced in any HirNode following the loop in the same scope
   - Recurses into nested If/While/DoWhile/For/Switch/Block bodies
   - Re-exported via crates/unlace-struct/src/lib.rs

3. Wired into `structure()` entry point so all SsaFunction → HirFunction
   paths benefit automatically.
   File: crates/unlace-struct/src/structurer.rs (line 43)

4. C printer support
   File: crates/unlace-output/src/c_printer.rs
   - collect_varnodes (HirNode::For arm): assigns SSA versions to init,
     body, then update in walk-order
   - emit_node (HirNode::For arm): renders body into a temp buffer first,
     then composes `for (init_str; cond; update_str) { body_str }`
   - Helper emit_for_clause + try_emit_increment_form +
     try_emit_compound_assign for short forms (`i++`, `i--`, `i += 2`)

CONSERVATISM RULES
==================
- Init must be a Statement IrInsn directly preceding the While in the same scope
- Init's output base varnode V identifies the induction variable
- Loop condition's base varnode must equal V
- Update IrInsn must:
  - Be the last Statement in the loop body
  - Have output == V
  - Be IntAdd or IntSub
  - Read V as an input
  - Have a constant step
- V must NOT appear in any HirNode following the loop in the same scope
- If any rule fails, the original [init; While] pair is preserved as-is.
