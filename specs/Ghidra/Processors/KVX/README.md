# Kalray KVX (kv3-1 Coolidge v1, kv3-2 Coolidge v2)

Native SLEIGH written for unlace (issue #98). No prior SLEIGH module exists.
`kvx_kv3_1.slaspec` and `kvx_kv3_2.slaspec` are generated by
`tools/gen_kvx_sleigh.py`. The generator reads each opcode's syllable masks,
operand bit fields, register names and modifier names from the GNU binutils KVX
opcode table (`opcodes/kvx-opc.c`) and the register-class switch of the binutils
disassembler (`opcodes/kvx-dis.c`), both passed on its command line; the bundle
model and the p-code are written in the generator. No text of either GPL file
is in this directory. Regenerate with:

```
python3 tools/gen_kvx_sleigh.py <binutils>/opcodes/kvx-opc.c <binutils>/opcodes/kvx-dis.c kv3_v1 \
    > specs/Ghidra/Processors/KVX/data/languages/kvx_kv3_1.slaspec
python3 tools/gen_kvx_sleigh.py <binutils>/opcodes/kvx-opc.c <binutils>/opcodes/kvx-dis.c kv3_v2 \
    > specs/Ghidra/Processors/KVX/data/languages/kvx_kv3_2.slaspec
```

(`kv4_v1` also generates; its table matches kv3-2 closely and is not shipped.)

Languages: `KVX:LE:64:kv3-1`, `KVX:LE:64:kv3-2` (64-bit mode). Calling
convention as GCC's kvx port uses it: arguments in r0-r11 then the stack, result
in r0 (r0:r1 for 16 bytes), return address in `ra`, stack pointer r12, r13 the
thread pointer, r14 the frame pointer, r18-r31 callee-saved.

## Bundle model

A KVX bundle (up to eight 32-bit syllables, bit 31 set on every syllable but the
last) decodes as one SLEIGH instruction. Syllables are routed to the issue slot
they occupy in the order the hardware assigns them: the first BCU-steered
syllable to BCU (a TCA opcode right after it to TCA), ALU-steered syllables to
ALU0, ALU1, then MAU and LSU, MAU and LSU syllables to their units, and every
later BCU-steered syllable is an immediate extension (IMMX) for the unit its
extension field names. Each slot's syllable and its IMMX words are saved in a
context buffer while the bundle is read; every slot is then decoded from its
buffer, so an instruction finds its extension words wherever they sit in the
bundle tail.

All slots compute into per-slot temporaries first and the register writes are
committed afterwards, so the bundle reads every source before it writes
(`copyd $r0 = $r1 ; copyd $r1 = $r0` swaps). The BCU transfer comes last.

## What is modelled

- Every kv3-1 and kv3-2 encoding binutils decodes in 64-bit mode (kv3-1: 4978
  forms, kv3-2: 5422 forms, counting each comparison or condition modifier value
  separately). Where binutils would take an earlier, more general table entry,
  the later one is dropped, so the decode matches objdump's choice.
- p-code for about 1,790 forms per core: `make`, `copyd`/`copyw`, `get`/`set`,
  `pcrel`, the 64- and 32-bit ALU operations (`addd`, `sbfd`, the
  `addx*`/`sbfx*` scaled forms, logic, shifts, `muld`/`mulw`, `maddd`/`msbfd`,
  min/max, `abs`/`neg`/`not`, sign and zero extension, `clzd`/`ctzd`/`cbsd`),
  `compd`/`compw` with every scalar comparison, `cmoved`, `extfz`/`extfs`/`insf`,
  every load and store width with the `.xs` scaled index and the conditional
  (`lsucond`) forms, `goto`, `call`, `icall`, `igoto`, `ret` and `cb` with
  every condition.

## Gaps

- The other forms (SIMD and packed arithmetic, floating point, the TCA
  coprocessor and matrix instructions, atomics, cache and TLB management, system
  calls, the `loopdo`/`loopgtz`/`loopnez` hardware loops) are named user
  operations (409 for kv3-1, 579 for kv3-2) over their source operands; the
  first operand gets the result when the syntax assigns to it.
- Hardware loops: `ls`, `le` and `lc` are plain registers; the loop-end
  branch is not modelled.
- 32-bit word operations write the zero-extended result; the upper half
  convention was not checked against hardware.
- Floating-point rounding, `.s` silent and the speculative/cached load
  variants (`.s`, `.u`, `.us`) only affect the listing.

## Decode check

Against `kvx-elf-objdump` (binutils 2.45) on randomly built bundles (each
syllable a random table entry with its free bits filled randomly, extension words
placed as the hardware expects): with up to four syllables, kv3-1 6,905 of 6,905
and kv3-2 6,851 of 6,851 objdump-decoded bundles print the same instructions,
operands and targets; with up to eight syllables (32 bytes, the decoder's
`MAX_INSTRUCTION_LEN`; 1,273 of 5,000 bundles longer than 16 bytes), kv3-1
4,927 of 4,927 and kv3-2 4,861 of 4,861.
